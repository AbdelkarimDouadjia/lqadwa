# Conversational assistant and provider readiness

This module adds natural-language answers, general non-medical questions and short follow-ups to the existing read-only assistant. Service questions retrieve the reviewed multilingual corpus; returned citation IDs are validated against those exact source snapshots. General answers have no fabricated service citations and carry a visible general-answer label. Citation validity is not proof that a generated explanation is correct or fully entailed by its sources.

## Current deployment boundaries

- Public `/assistant`: existing local help, catalog, participating-pharmacy directory and owner-scoped request reads continue unchanged. `ASSISTANT_CHAT_ENABLED` defaults OFF. Enabling it would send consenting users' questions to Cloudflare AI (with separately authorized free OpenRouter as optional backup) and requires separate operator privacy/provider acceptance and a successful production-provider check. This change does not record that acceptance.
- Private `/operations/assistant/chat`: root owner, provider-verified recent MFA and `ASSISTANT_NVIDIA_EVALUATION_ENABLED=true` are all required. Opaque native sessions cannot bypass these guards, even with an owner cookie. NVIDIA is first; explicitly enabled Cloudflare AI is the backup. If Cloudflare is unavailable in configuration, a separately authorized OpenRouter credential may be the backup. At most two configured providers are attempted. With neither selected provider working, the assistant returns the actual local sources or honestly abstains.
- `ASSISTANT_NVIDIA_API_KEY_V1` is a Cloudflare Worker secret. It is never a public environment variable, browser field value, bundle, API response or Git file. The owner settings page displays only configured/available metadata and the private evaluation link. Rotating this bootstrap credential requires replacing the server secret; it is separate from the existing seven-provider encrypted database settings.
- The user's unidentified second credential is retained only in the private Windows DPAPI recovery store, unassigned and not sent to guessed providers. A prefix alone cannot establish its issuer. No automatic DeepSeek routing is configured.

An excerpt-only OpenRouter activation is **not** conversational consent. Chat additionally requires `ASSISTANT_OPENROUTER_CHAT_KEY_VERSION` to match the current credential's positive key version and `ASSISTANT_OPENROUTER_CHAT_ACCEPTANCE_REFERENCE` to contain separately recorded operator authorization for sending questions/history. Both default unset. Record actual acceptance before setting these; do not fabricate a reference. Rotation/removal changes the key version and invalidates that authorization. The credential/version is rechecked before use, and user consent is independently required. This opt-in uses reviewed Worker configuration and deployment history; it needs no schema change.

NVIDIA's API Trial Terms section 1.4 restrict trial access to internal testing/evaluation without a separate production subscription. Its catalog notice also discloses input/output recording; section 2.6 excludes sensitive/personal/health data. Therefore the NVIDIA trial route is **never available to ordinary users or pharmacies**, regardless of the public-chat flag. No paid subscription, API credits or infrastructure was purchased. The trial integration is not a production entitlement.

## Cloudflare free production-provider path

The account's Workers plans page showed **Free / $0 / Current plan** on 29 October 2026. Workers AI includes 10,000 Neurons/day on Workers Free and rejects excess usage instead of enabling paid overage. No upgrade, paid gateway credits or alternate paid model is configured. The application additionally caps all model attempts to 20/day, shared with tests/probes through the app. Other account workloads share the platform allowance. If an operator deliberately changes the account plan later, review or disable inference first; the app does not change billing plans.

The fixed model is `@cf/qwen/qwen3-30b-a3b-fp8`, using standard inference without AI Gateway logging, prompt storage or stateful training features. Cloudflare's current policy states zero retention for standard inference (subject to stated exceptions) and no model training on customer content. This differs from NVIDIA's trial recording notice. A live local-only binding probe on public/synthetic English, French and Arabic questions returned HTTP 200, general/grounded output and valid source IDs. An initial probe explicitly using `--local` could not use AI; it was corrected to the documented remote binding, without deploying a diagnostic endpoint.

`ASSISTANT_CLOUDFLARE_CHAT_ENABLED=true` and `ASSISTANT_CLOUDFLARE_FREE_CONFIRMED=true` allow the binding for the MFA-protected owner evaluation. Public selection also requires a genuine `ASSISTANT_CLOUDFLARE_CHAT_ACCEPTANCE_REFERENCE` (minimum eight characters), independently of `ASSISTANT_CHAT_ENABLED=true` and per-user consent. No acceptance reference is fabricated or inferred from an excerpt-only key consent. These default unset. No additional API key is required. Keep public generation OFF while operator acceptance or quality gates are unresolved.

Production declares the normal `AI` binding. Isolated CI creates a separate generated Wrangler config in the same output directory with that remote binding removed; production config remains intact. CI never initializes/calls the remote AI binding or uses live credentials.

The isolated entry also drains unused request bodies, matching Wrangler's bundled development middleware. This prevents its documented `no_bundle` proxy connection loss after early rejection ([upstream issue](https://github.com/cloudflare/workers-sdk/issues/15203)). Production entry/configuration and all rejection assertions stay unchanged. A regression sends rejected uploads followed by health reads without retrying mutations.

## Consent, privacy and controls

Conversation mode requires a new unchecked consent box. Only the current question, at most two previous user questions from generated conversation turns and up to three public excerpts are submitted. Account/request tool results, catalog results, prescription files/OCR, GPS, cookies and account IDs are not included. Switching tabs and clicking an older record action preserves its authorized structured tool; it must not turn private record labels into an LLM prompt. Conversations stay in component memory and are not stored by LQADWA. Provider retention is separate and disclosed for the private trial.

Clinical/dosing and common personal-data/credential patterns are checked before transmission and generated output is screened. These patterns are defense in depth, **not a guarantee of detecting every diagnosis or personal detail**. Do not submit patient data to the trial. Production handwriting recognition remains disabled. Diagnosis, dose selection, substitutions, stock claims and model-executed tools remain outside this module.

Provider URLs and model IDs are server-owned. The NVIDIA evaluation model is `nvidia/nemotron-3.5-lightning-30b-a3b`, verified against its official current catalog entry. OpenRouter uses only `openrouter/free`, zero price ceilings, no paid fallback and the existing privacy filters. The unidentified key never becomes a provider/model/URL selector.

Each primary/backup attempt consumes the shared 20/day global model-attempt budget, including failures. There is no repeat attempt to the same provider. Upstream failures open a provider-specific 60-second circuit; caller cancellation never opens the shared circuit. Per-provider deadline is seven seconds, total generation deadline fifteen seconds, client deadline twenty seconds. Responses are byte-limited, strict JSON and plain text, with no model-generated HTML, URLs, SQL or arbitrary tools. Missing keys, invalid output, timeout, quota exhaustion and unavailable providers return the non-model fallback. Existing authenticated-account limits remain in force.

## Verification and operator actions

The offline RAG tests cover generated service/general answers, consent, forged citations, primary/backup ordering and budgets, blocked private/clinical/live questions, cancellation, fixed endpoints and free-only constraints. HTTP/D1 tests cover root/client/native isolation and the disabled public-chat gate. Browser tests cover consent-before-send, real local-source fallback, four languages, both themes and narrow layouts. These use synthetic local fixtures and mocked provider responses, never production patient records.

A separate live internal evaluation on 29 October 2026 used the supplied NVIDIA credential and synthetic/public questions only: HTTP 200 for English general knowledge, French source-grounded privacy help and Arabic source-grounded pickup help. No paid plan was enabled. This is a connectivity/format check, not clinical, Kabyle-language or production acceptance. Credentials exposed in chat should be revoked/replaced before distribution.

To evaluate privately, sign in as owner, verify MFA, open Assistant providers → Private NVIDIA conversation and consent using non-personal questions. To use OpenRouter as an optional backup, save/test/enable a free OpenRouter credential in the existing owner settings, then have the operator record the separate version-bound chat authorization described above. Public conversational deployment still needs documented operator privacy/provider acceptance and quality/red-team evaluation; the Cloudflare path does not need another provider key. Keep the public flag OFF until those pass. Existing mailbox delivery, owner MFA recovery, legal acceptance, participating-pharmacy round trip and physical signed-Android upgrade checks remain independent release gates.
